# AGENTS.md

Guidance for agents and maintainers. `CLAUDE.md` imports this file. Keep it, [README.md](README.md) (user docs) and [TESTING.md](TESTING.md) (manual test checklist) up to date with code and workflow changes, and [SECURITY.md](SECURITY.md) when security controls or the threat model change; no other agent tooling or memory files are needed.

## Project

- `img_tagger.py`: single-file CLI that tags JPEG/WebP/PNG/GIF files with a vision-language model on Ollama or LM Studio (local or LAN) and writes the tags into image metadata. `--clear` strips metadata again (no backend needed).
- `prompt.txt`: the prompt; overrides the `DEFAULT_PROMPT` fallback in code.
- Flat, not installable (`pyproject.toml` only holds Ruff and coverage config). Tests in `tests/` (pytest, `pytest.ini`). Python **3.13+**.
- Design goal: a plain script with minimal dependencies whose value is reliable metadata/format handling. Prefer small local fixes over new modules or dependencies.
- Git: work on a branch and open a pull request rather than pushing to `main`.

## Commands

Commands use `python3` (on Windows `python`).

- Install: `python3 -m pip install -r requirements.txt` (runtime; both backend clients are imported at startup, so install all of them even for `--clear`) and `-r requirements-dev.txt` (pytest, pytest-cov, pinned Ruff).
- Lint/format: `ruff check .`, `ruff format .` (CI runs `ruff format --check`; line length 120).
- Tests: `python3 -m pytest` (offline: generated images, fake backends); `python3 -m pytest --cov` like CI.
- Integration tests (opt-in, live backend, images in git-ignored `test_images/`): `python3 -m pytest -m integration --run-integration -s [--tagger-backend lm-studio] [--tagger-host URL] [--tagger-model M] [--images-dir DIR]`. `--tagger-model` defaults to `qwen3-vl:8b`, so pass LM Studio's id with LM Studio. The `client` fixture uses `_create_client()`. See [TESTING.md](TESTING.md).
- Run: `python3 img_tagger.py <dir> [-r] [--backend lm-studio --model qwen/qwen3-vl-8b] [--workers 1-4] [--timeout 600] [--max-pixels 1] [--log run.log] [--clear]`.

SonarQube Cloud (project `juusolatva_img_tagger`) runs in CI: keep functions under cognitive complexity 15 by extracting `_private` helpers.

## CI

`.github/workflows/ci.yml` runs on pushes to `main`, pull requests and manual dispatch. Every job has `timeout-minutes`; checkouts use `persist-credentials: false`. All actions and reusable workflows are pinned to full commit SHAs with a `# vX.Y.Z` comment.

- **Ruff**: `ruff-action` reads the version from the `ruff==` pin in `requirements-dev.txt`.
- **Lockfile**: recompiles `requirements-dev.lock` with the pinned `uv` and fails on any diff. Keep the `uv==` pin in `ci.yml` in step with your local uv.
- **Tests**: Ubuntu with Python 3.13 and 3.14, `windows-latest` with 3.14 (`fail-fast: false`). Installs `requirements-dev.lock` with `--require-hashes --only-binary :all:`, so every locked package needs wheels for all matrix versions and OSes. The 3.14 jobs upload `coverage.xml` as artifacts `coverage` (Linux) and `coverage-windows`; Sonar reads both, so Windows-only branches count as covered.
- **SonarQube Cloud**: scans with both coverage reports; settings in `sonar-project.properties`. Needs `SONAR_TOKEN` as an Actions secret *and* a Dependabot secret. `if:` can't read secrets, so the token is mapped to a job env var and the steps run only when it's set; otherwise a warning explains the skip. Fork PRs get no secrets and no scan, so don't make the Sonar status a required check.
- **Coverage** (`[tool.coverage.run]`): branch coverage, `relative_files = true` (Sonar path mapping), `patch = ["subprocess"]` so `test_cli.py` subprocess runs count. This leaves a harmless empty `.coverage.<host>.pid…` file (git-ignored).
- **OSV-Scanner** (`osv-scanner.yml`): full scan on `main` pushes, weekly and manual; diff scan on PRs and `merge_group` (SARIF upload disabled on fork PRs). Both pass `--lockfile=requirements.txt:requirements-dev.lock --no-resolve -r ./`.
- **Dependabot** (`dependabot.yml`): Actions and pip (grouped minor/patch, one PR per major). It edits only `requirements*.txt`, never the lock, so its PRs fail the Lockfile job until you regenerate the lock and push it to the PR branch.
- **Regenerating the lock** (after changing either requirements file): `uv pip compile requirements-dev.txt --universal --python-version 3.13 --generate-hashes --no-header -o requirements-dev.lock`. Add `--upgrade` (all) or `-P <package>` to bump versions.
- Changing the supported Python range means updating together: the CI matrix, `sonar.python.version`, Ruff `target-version`, the lock's `--python-version` and the README Python badge.

## Backends

- `--backend ollama` (default, `http://localhost:11434`): `ollama` client; `get_tags_ollama()` passes the guarded image bytes, so a remote server needs no shared filesystem.
- `--backend lm-studio` (`http://localhost:1234`): `openai` client against `f"{host.rstrip('/')}/v1"`; the image goes as a base64 data URL. `api_key="lm-studio"` is a required placeholder.
- `--model` defaults to `qwen3-vl:8b` (Ollama naming) for both; LM Studio ids differ (`qwen/qwen3-vl-8b`, see `<host>/v1/models`).
- `--host` has no argparse default: `process_directory(host=None)` fills it from `DEFAULT_HOSTS`, so the ollama client never falls back to `OLLAMA_HOST`.
- **LM Studio vision** (found by testing): a GGUF model is vision-capable only with its `mmproj-*.gguf` downloaded; otherwise HTTP 400 `does not support image inputs`.
- **Image sent to the model** (`_model_image()`): first frame, `exif_transpose()`, scaled down (never up) to `--max-pixels` megapixels (default `DEFAULT_MAX_MEGAPIXELS` = 1.0; JPEG via `draft()`), 16-bit PNG mapped to 8-bit, re-encoded as PNG (PNG/GIF sources or transparency) or JPEG quality `MODEL_JPEG_QUALITY` (90) with **no metadata**: clear `frame.info` after `convert()`, because Pillow carries it through and writes back a JPEG comment and PNG ICC profile. LM Studio's MIME type follows the encoding. `--max-pixels 0`, or any `Exception` while building the copy (Pillow also raises `struct.error`, `zlib.error`, `TypeError`), sends the original bytes with the Pillow-detected MIME type (fallback `image/jpeg`); that fallback is only logged. Why 1 MP (measured 2026-10, Qwen3-VL 4B): Ollama enlarges smaller images to ~1,200 tokens anyway; diagram labels were readable at 1 MP but not 0.5; a 12 MP photo took 29 s vs 5 s.
- **Client hardening** (`_create_client()`): both SDKs follow redirects by default, which would let the server forward the image and prompt anywhere, so both use `follow_redirects=False` (LM Studio via `http_client=DefaultHttpxClient(...)`); a redirect fails the request. The ollama client adds `OLLAMA_API_KEY` as a bearer token to every host, so `auth=_without_authorization` removes the header per request (an empty header still triggers the fallback). The openai client's `OPENAI_ORG_ID`/`OPENAI_PROJECT_ID` headers are removed with `Omit()` in `default_headers`. `trust_env` stays on (proxies work). `TestClientHardening` checks the real clients against a local redirecting server. Clients are closed after use, so test fakes need `close()`.
- **Server check** (`_check_server()`): before any image, list models with its own client and timeout `min(--timeout, SERVER_CHECK_TIMEOUT)` (10 s), so an unreachable host fails fast. Any exception or an unlisted model raises `_ServerCheckError` (lists available models plus a hint) → `main()` exits 1. `_model_matches()`: exact name; Ollama also `<name>` for `<name>:latest`; LM Studio also `<id>@<quant>`. Runs after `_load_prompt()`, not for `--clear`, and deliberately before any skip check (a fully tagged folder also exits 1 when the server is down; checking lazily would need an abort path through the pool). It doesn't test vision support. Test fakes list `conftest.FAKE_MODELS`; `test_cli.py` uses the `failing_ollama` stub server to reach per-image failures.
- **Timeout**: `--timeout` (default 600 s, must be > 0 and finite: `math.isfinite()` rejects `nan`, which `<= 0` lets through, and `inf`, which overflows socket timeouts) covers the whole non-streamed reply including model loading. LM Studio uses `max_retries=0`: retries would resend to a server still busy with the timed-out request. An empty `choices` list or a `None` reply counts as empty.

## Architecture

- **CLI**: `main(argv=None) -> int` parses (`_build_parser()`), validates with `_log_path_error()` and `_argument_error()` (workers 1–4, timeout and max-pixels finite) *before* `setup_logging()`, so invalid arguments create no log file. Validation errors, log-open failures, `_ServerCheckError` and `OSError` from `process_directory()` (e.g. an `_UnsafeImagePath` folder) print `Error: …` and return 1. `__main__` is only `sys.exit(main())`. Argument handling is tested in-process (`TestMain`); subprocess tests cover logging and console encoding.
- **Pipeline**: `process_directory()` → `_find_images()` (extension filter, `iterdir()`/`rglob()`; the root is opened with `os.scandir()` first because `rglob()` silently yields nothing for an unlistable folder; returns an ordered `dict` path → `lstat` of regular files) → `_load_prompt()` → `_check_server()` → `_create_client()` → quit listener → `_run_tasks()` (`ThreadPoolExecutor` + `as_completed` + tqdm; results go to `_RunStats.record()`) → `_print_report()`.
- **Per image** (`process_single_image()`): stop check (`CANCELLED`, before reading) → one guarded read `_read_image_snapshot()` (bytes + `stat`; all later steps use these bytes) → `get_image_format(data)` (Pillow verify; invalid or outside `TAGGABLE_FORMATS`, e.g. BMP/MPO → `FAILED` before any model call) → `is_already_processed()` (`SKIPPED`) → backend call → `parse_model_output()` → `tag_image(expected=snapshot)`. The edit refuses a file that `_same_version()` (identity, size, `st_mtime_ns`) says changed since the snapshot (`File changed during processing`), so tags never describe other content. Exceptions escaping a worker are counted and listed by `_run_tasks()`.
- **Format dispatch**: tagging, skip detection and clearing route on the Pillow-detected format, not the extension; the extension decides only when Pillow can't read the file (`_is_gif()`).
- **Workers**: default 1, max 4 (both backends' default concurrency). Enforced in `_argument_error()`, not in `process_directory()`. The cap is deliberate; don't propose raising it.
- **Prompt**: `prompt.txt` next to the script wins; if it exists but is unreadable or empty → `sys.exit(1)`; missing → warning and `DEFAULT_PROMPT`. `DEFAULT_PROMPT` is implicitly concatenated literals: keep the trailing space on each piece.
- **Concurrency**: pyexiv2 isn't thread-safe; every pyexiv2 read, write and clear holds `metadata_lock`, and only around the pyexiv2 calls (not the Pillow auto-heal re-save or the file replacement). Model calls, GIF editing and Pillow work run outside the lock.
- **Graceful quit**: `Q` sets `stop_event` via the daemon `listen_for_quit()`. Windows: `_wait_for_quit_windows()` (`msvcrt`), discarding the scan code after a `\x00`/`\xe0` prefix (Page Down is `\xe0` `Q`). POSIX: `_cbreak_stdin()` + `_wait_for_quit_posix()` reading the raw fd with `os.read()` (Python's buffer would hide keys from `select()`); non-tty stdin is polled with `idle_sleep=0.1`; unusable stdin (`None`, closed, `StringIO`) logs at debug and returns. In-flight requests finish; queued tasks return `CANCELLED` (not printed or counted). `process_directory()` sets `stop_event` in `finally` so the listener exits and restores the terminal.

## Tag parsing and normalization

- `normalize_tags()`: strip, lowercase, order-preserving dedup, cap 12, drop tags over `MAX_TAG_LENGTH` (64: such entries are sentences split by the comma fallback). Nothing else is rewritten: underscores and non-English tags stay on purpose (`prompt.txt` may ask for any language). Fewer than 6 tags → `FAILED`.
- `parse_model_output()` returns `None` for empty content; drops everything up to the last `</think>` (a `<think>` without `</think>` → `None`: cut-off reasoning has no answer); removes code-fence lines (also CRLF); returns `None` for a reply *opening* with an English refusal (`_REFUSAL`, only whitespace or Markdown emphasis before it; `["` and `- ` aren't skipped, so a list whose first tag is `i can't even` still parses). Then tries in order:
  1. JSON array (whole string, else first-to-last bracketed segment; strings and numbers kept, booleans dropped). A JSON list containing strings is authoritative: fewer than 6 → `None` (comma-splitting JSON would produce `[true`-style tags). A list without strings (e.g. `[1]` in prose) falls through.
  2. Bullets at line start (`-•★●`, or `*` followed by a space so `**Tags:**` isn't one), ≥ 6 items.
  3. Numbered lists (`\d+\.`), ≥ 6 items.
  4. Intro: `tags`/`keywords` within the first ~40 chars followed by a colon on the same line, or a dash right after; parsed by `parse_text_tags()` (drops English stop words, keeps `3d`/`ui`).
  5. Comma- and/or newline-separated fallback.

  A matched bullet/numbered/intro pattern returns its result (or `None`) without trying later ones. Bullet and numbered lines are also split on commas and stripped of quotes.

## Metadata

- **JPEG/WebP/PNG**: `Exif.Photo.UserComment` = `"<tags>, ... [PROCESSED BY AI]"`, `Xmp.dc.subject` = tag list, `Xmp.dc.description` = `"Tags: <tags> | [PROCESSED BY AI]"`. Only these three are replaced; other EXIF/XMP/IPTC survives (unless auto-heal runs).
- **GIF**: the comment only, replacing any existing one.
- **Skip marker** (`is_already_processed()`): `[PROCESSED BY AI]` in any EXIF/XMP value (`_pyexiv2_has_marker()`), else any string in Pillow's `img.info` (`_pillow_has_marker()`, e.g. PNG text chunks); GIF: comment only. Not validated. Unreadable metadata → `_warn()` and treated as untagged.
- **`--clear`**: `clear_directory()` → `clear_tags()` per file (validate a guarded snapshot, then `_image_edit(expected=snapshot)`); no prompt, client, listener or report; per-file failures are printed, not raised. Standard images: `_clear_all()` strips EXIF, XMP and IPTC. XMP needs `clear_xmp()` *and* `modify_raw_xmp("")` (on WebP `clear_xmp()` alone leaves the chunk). `clear_comment()` is never called, so JPEG `COM` and PNG text chunks survive (a marker there still causes a skip). GIFs: `_set_gif_comment(source, "")` removes every comment block.
- **PNG chunks**: pyexiv2 edits in place, so other text chunks, `pHYs` and private chunks survive; tagging adds `eXIf` and an `iTXt` `XML:com.adobe.xmp` chunk, clearing removes both. Exiv2 rewrites a `tEXt` `Description` as `iTXt`.
- **GIF editing** (`_set_gif_comment()`): never decodes; walks the blocks (header, screen descriptor, global color table, `21` extensions, `2C` images with their sub-blocks), drops every `21 FE` comment and, when tagging, writes one UTF-8 comment right after the header (where Pillow reads `info["comment"]`). Every other byte is copied (Pillow's re-encode used to drop `disposal=2`). `GIF87a` → `GIF89a` only when a comment is written. A missing trailer is added at a block boundary; bytes after the trailer are kept; a GIF ending inside a block raises `ValueError("Truncated GIF file")`.
- **Animated images**: the model sees only the first frame. pyexiv2 edits WebP in place, keeping frames.
- **Auto-heal**: a pyexiv2 `RuntimeError` containing `IFD` or `corrupt` (case-insensitive) → `_sanitize_with_pillow()` re-saves the snapshot into the temporary (`quality=95`, detected format; animated WebP/APNG with `save_all=True`, durations and loop, refused over `MAX_ANIMATION_PIXELS` = 250 M frame pixels). Tagging retries the pyexiv2 write once (a second failure → `FAILED`); clearing doesn't retry (the re-save *is* the clear). The re-save drops EXIF (incl. orientation), XMP, IPTC, DPI, PNG text chunks and for JPEG/WebP the ICC profile, and makes lossless WebP lossy.

## File safety

The core invariant: read every image once through guarded handles, write through an exclusively created temporary in the same folder, and replace only if the source is still the same file. Never reopen paths by name in between.

- **pyexiv2 never gets a path**: use `pyexiv2.ImageData` on bytes and write `get_bytes()` back ourselves. On Windows pyexiv2 can't open paths with non-ASCII characters anywhere in them. (`ImageData` refuses files ≥ 2 GB.)
- **Reads** (`_read_image_bytes()` → `_image_parent()` + `_source_bytes()`): Pillow and both backends only see byte snapshots. `_source_bytes()` refuses a file whose identity differs from the `lstat` taken at discovery (`File changed since it was found`, against folder swaps between discovery and read), nonregular files, symlinked ancestors, and files over `MAX_IMAGE_BYTES` (256 MiB, checked on `st_size` and by reading at most one byte more). Paths with `..` are refused, except leading `..` parts, which `_find_images()` resolves against `os.getcwd()` (`_without_leading_parent_refs()`).
- **POSIX**: parents and leaf opened with `O_NOFOLLOW`, directory descriptors pinned, descriptor-relative create/replace/unlink (`dir_fd`). `O_NONBLOCK` at open refuses FIFOs; reads switch back to blocking. The final image folder must belong to root or the current UID and not be group/other writable (`_check_directory()`, with a `chmod go-w` hint; user-private groups with umask 0002 can't be told apart from shared groups, so they're refused too). Ancestors are pinned rather than trusted by owner (overflow UIDs in user namespaces). Same-UID or root attackers are out of scope.
- **Windows**: every ancestor is pinned with `_pin_windows_directory()` (`CreateFileW` with `FILE_TRAVERSE`, else `FILE_LIST_DIRECTORY`, and no `FILE_SHARE_DELETE`, so the folder can't be renamed or swapped for a junction; a handle with only `FILE_READ_ATTRIBUTES` does *not* block renames, so folders granting neither right are refused). `_win_open()` always adds `FILE_FLAG_OPEN_REPARSE_POINT`; any reparse point is refused. There is no equivalent of the POSIX folder-writability check.
- **Temporary** (`_image_edit()`): random `tmp<hex>.tmp` in the image's folder, created exclusively (POSIX `os.open(..., dir_fd=parent_fd)`, Windows `_create_windows_temp()` with `CREATE_NEW` and share mode 0) so the replacement stays on one filesystem. The descriptor is kept through all writes (`_temp_file_object()`), and pyexiv2 and Pillow write through its file object.
- **Permissions** are captured from the source descriptor (only for edits) and applied to the temporary, never broader than the source:
  - Mode via the descriptor. No `copy2`/`copymode`; timestamps are not copied.
  - POSIX group: `_restore_group()` `fchown`s the temporary to the source's group so kept group bits don't apply to the folder's group. If that fails (`EPERM`, `EINVAL` for unmapped gids, `EOPNOTSUPP`), group bits are dropped with `_warn()` and other bits are limited to the owning group's rights (`_owning_group_bits()`; with a POSIX ACL the mode's group bits are the mask, so the `ACL_GROUP_OBJ` entry is read instead).
  - Linux xattrs (`_kept_xattr()`, `_restore_xattrs()`): `system.posix_acl_access` (read failures other than `ENODATA` propagate; inherited default-ACL entries on the temporary are removed, fail closed), readable `user.*`, and `security.selinux` best effort (failure logs at debug; the folder's default label stays). Other `security.*`/`trusted.*` are dropped.
  - Windows: on volumes with `FILE_PERSISTENT_ACLS` the source DACL is captured (`GetSecurityInfo`) and the temporary is *created* with it; `_create_windows_temp()` compares entries and the protected flag (`_windows_dacl()`; `CreateFileW` drops the `AI` flag) and fails closed on any other difference. `SetSecurityInfo` is deliberately not used (it recomputes inherited entries). The owner becomes the current user; `_apply_permissions()` sets only the read-only attribute.
  - EFS: an encrypted source is refused if the temporary isn't encrypted (`_efs_encrypted()`), so the image never becomes plaintext.
- **Commit**: check the temporary's identity and `_same_version()` on the source, then `robust_replace()`: up to 10 attempts 0.5 s apart on any `OSError` (Windows locks), final error chained. POSIX uses `os.replace` with `dir_fd`. Windows renames the open temporary through its handle (`_rename_windows_handle()`: `FileRenameInfoEx` with replace + POSIX semantics + ignore read-only, falling back to `FileRenameInfo` on `ERROR_INVALID_FUNCTION`/`NOT_SUPPORTED`/`INVALID_PARAMETER`; name sized in UTF-16 code units and copied as raw bytes; relative targets refused). Read-only images stay read-only on NTFS.
- **Cleanup**: POSIX `unlink` with `dir_fd` in `finally`. Windows discards the temporary only on failure, in `except BaseException` before the handle is closed: `_discard_windows_temp()` (clear read-only, delete-on-close) acts only if the handle still sits at the temporary's name, because after a completed rename (e.g. Ctrl+C right after it) the handle *is* the image.

## Logging and console output

- The `img_tagger` logger has a `NullHandler`: without `--log` nothing is logged. Results go to the console via `tqdm.write()`/`print()`. Problems the user must always see go through `_warn()` (logs and prints `  Warning: …`): metadata read failures in `is_already_processed()`, auto-heal, and `_restore_group()` failures.
- `setup_logging()` adds a `_LogHandler` to the root logger (not `basicConfig()`, which silently ignores new handlers when the root already has one, e.g. pytest's); our logger at `DEBUG`, others at `INFO` via a filter (Pillow's per-chunk noise dropped, httpx request lines kept); the root level is raised to `INFO` if needed but never lowered. A second call replaces and closes the earlier handler.
- The log holds settings, prompt, outcomes, timings, raw replies (cut to `MAX_LOGGED_REPLY_CHARS` = 4000 by `_log_excerpt()`), tracebacks and a summary. `_LogFormatter` escapes control characters with `_shown()` so names or replies can't fake records (tracebacks unescaped).
- **Log path safety**: raw replies can be steered by text in an image, so a misused `--log` must not be able to append to shell profiles or keys. `_log_path_error()` (early check): must end in `.log` (any case) and, if it exists, be a regular file and not a symlink. Not confined to the current directory on purpose (`--log /tmp/run.log` must work). `_open_log()` then opens once: POSIX `O_NOFOLLOW | O_APPEND | O_CREAT | O_NONBLOCK`, new files `0o600`; Windows `CreateFileW` with `FILE_APPEND_DATA | READ_CONTROL`, reparse points refused, new files get the owner-only DACL `_Win.PRIVATE_SDDL` (`D:P(A;;FA;;;OW)`). The file must be regular and owned by the current user (`_owned_by_current_user()`; Windows compares the owner SID with the token's user and default-owner SIDs, since an elevated admin's files may belong to Administrators). The stream is written with `errors="backslashreplace"` (non-UTF-8 POSIX names arrive as surrogates). Ancestor folders resolve normally (macOS `/tmp` is a symlink).
- **Console**: names and messages from files or servers go through `_shown()` (C0/C1 controls and bidi overrides escaped, other Unicode kept). `main()` reconfigures `sys.stdout` with `errors="replace"`: a redirected Windows console uses cp1252, which can't encode `[✓]` or many names (tested via a subprocess with `PYTHONIOENCODING=ascii`).

## Tests and known limitations

- `conftest.py` sets `umask 0o022` (autouse) so test folders pass `_check_directory()`; `other_group_or_skip()` only returns a secondary group a probe file can really be `chown`ed to. Windows-only tests are marked `windows_only` in `test_file_safety.py`; the `msvcrt` listener is tested with a fake module.
- `test_cli.py::test_unreachable_server_stops_before_any_image` takes ~10 s under WSL2 mirrored networking (connects to closed localhost ports aren't refused); not a bug.
- **Known bugs**: none pinned. Pin new ones as strict `xfail` (a fix makes it XPASS → remove the marker).
- **Untested** (see [TESTING.md](TESTING.md)): tagging quality, Windows FAT32/exFAT and SMB shares (a server that rewrites DACLs on create, e.g. Samba without `vfs_acl_xattr`, would make the fail-closed DACL check reject every image there; deliberate), real-console `Q` on Windows, macOS entirely, and the `>=` dependency minimums (CI only tests the lock). Try a tag and `--clear` on a USB stick and a network folder before merging changes to Windows file safety.
- **SonarQube accepted issue**: `pythonsecurity:S8707` path traversal on `--log` in `_open_log()`: mitigated by `_log_path_error()`, which Sonar doesn't recognize. Its suggested fix (confine to the current directory) breaks absolute log paths.
- **SonarQube false positives** (dismissed; don't "fix" in code): regex backtracking on `parse_model_output()` patterns (measured linear on 200k-char adversarial input); `python:S9152` in `_image_edit()` (the code after `yield` is the commit and must not run when the `with` body raises; cleanup is in `except BaseException`/`finally`).
