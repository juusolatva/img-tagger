# Tech stack
- Python ≥3.10 required (PEP 604/585 annotations); CI matrix 3.10–3.14 (Linux only). Dev machines: Fedora Linux and Windows 11, both Python 3.14. On Windows the POSIX-only tests (quit listener, permission bits) skip and the `msvcrt` Q listener is still untested.
- Runtime deps (`requirements.txt`, `>=` lower bounds only, never tested as minimums): `ollama`, `openai` (LM Studio OpenAI-compatible API), `pillow`, `pyexiv2` (Exiv2 binding; not thread-safe; can't open non-ASCII paths on Windows, so only fed bytes), `tqdm`.
- Dev deps (`requirements-dev.txt`): pytest, pytest-cov, `ruff==` exact pin (CI reads Ruff version from it). `requirements-dev.lock` = uv-generated hash lock, used only by CI; regen command + gotchas in `AGENTS.md` CI section.
- Not packaged: `pyproject.toml` holds only `[tool.ruff]` (py310, line-length 120, default rules) and `[tool.coverage.run]`. pytest config in `pytest.ini`.
- CI: GitHub Actions `.github/workflows/ci.yml` — Ruff check + format check, pytest+coverage matrix (Linux only), SonarQube Cloud scan (`sonar-project.properties`; `SONAR_TOKEN` as Actions + Dependabot secret; scan step gated on `env.SONAR_TOKEN != ''`, so fork PRs skip with a warning and get no quality-gate status). Jobs have `timeout-minutes`, checkouts `persist-credentials: false`. `.github/workflows/osv-scanner.yml` — `google/osv-scanner-action` reusable workflows (full scan on push/schedule/manual, PR diff scan on PR/merge_group with `upload-sarif` skipped on fork PRs; scans `--lockfile=requirements.txt:requirements-dev.lock --no-resolve -r ./`). `.github/dependabot.yml` (schedule/grouping/cooldown live only there): GitHub Actions; pip entry ignores `*` (also blocks security PRs) because Dependabot can't regenerate the uv lock. Lock bumps are manual: regen command + `--upgrade`/`-P <pkg>` (plain regen keeps existing pins). Dismissed Sonar false positives listed in `AGENTS.md`.
- Backends: Ollama `http://localhost:11434`, LM Studio `http://localhost:1234`; one `--model` default `qwen3-vl:8b` (Ollama naming; LM Studio ids differ, e.g. `qwen/qwen3-vl-8b`, so pass `--model`). LM Studio accepts images only if the GGUF model's vision projector (`mmproj-*.gguf`) is downloaded, else HTTP 400 "does not support image inputs". Both clients get `--timeout` (default 600s) via `_create_client()`; LM Studio client has `max_retries=0`.
- Also installed locally, NOT configured in repo: `basedpyright` (Serena LSP via `project.yml`) and, on Fedora, `black`. Their output reflects user-global defaults; never use black (Ruff format is authoritative).
